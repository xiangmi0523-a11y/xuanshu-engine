## 5. 八字、六爻端到端结果

两个用例：

- **E2E-BZ-1**：1990-06-15 14:30，北京，夏令时 UTC+9，gender = UNKNOWN，CFG-02 = false。
- **E2E-LY-1**：2026-11-21 12:00，UTC+8，爻 7 8 9 6 7 8。

计算结果：

- 八字：庚午 壬午 辛亥 乙未；大运因 MISSING_GENDER 省略（OK_WITH_DEGRADATION）。
- 六爻：本卦水火既济（坎宫三世），变卦泽雷随；日辰己亥，旬空辰巳。日辰所用的日界来自 S-10 模拟变体内容中的 00:00，只为让路径可执行。

## 12. 实现说明、差异与根因（请审查）

1. **Q-3（Source / Edition 基础字段）**：授权书所称的《玄枢数据契约_v0.1.1-draft.md》没有随附。本轮只建 v1.0 字段，著录字段【待定】，没有自造书目数据。
2. **Q-7（evidence_role）**：按裁决暂用四值。
   - evidence_link 的主键是（证据, 子项, 角色），因此同一证据挂同一子项时可以并存多个角色。
   - Muse 并行核查（M-5）结论：四类不互斥、四类不穷尽、“异文记录”宜作独立文本关系，并给出八条字段建议。报告已归档于数据仓库 crosscheck/muse/。
   - 是否改契约由用户与 GPT 裁决，本轮不改表。
3. **Q-12**：config 参数条目在清单 §6.4(2) 的 {param_id, value, value_source} 之上增加了 apply_mode。依据是 Q-12 裁决“存储并纳入配置指纹”。
   - 集合排序键为 param_id（DB-H-18）。
   - 六爻空参数集写 `[]`。
   - stored_only 参数不进依赖行，也不触发 PARAM_PROVISIONAL 或 Q-C-04。
4. **判定顺序**：§9.3 没有单列 PATH 阻断（P-38），本实现的读法如下：
   - 第 1 步：BLOCKED-HARD。
   - 第 2 步：争议未裁决且无可选变体、变体未选、缺参数。
   - 第 3 步：登记、批准、准入。
   - 3b 步：PATH 的 BLOCKED-FORMAL。
   - 第 4 步：NON_FORMAL 原因。

   这个顺序使 G0、G1 两用例的审计码与清单 DB-B-03 完全一致。
5. **block_reason_code 格式**：MISSING_APPROVAL 按 DB-B-03 写裸码，所缺批准的变体在判定结果的 object_id 中，不进审计。其余审计码写“类别:对象:步骤”。
6. **暂按口径**：用未裁决的 dispute 表达（§5.3）。object_ref 约定为 `function:` / `component:` / `param:` 前缀。PARAM_PROVISIONAL 只对实际执行步骤读取的参数生成。
7. **blocker_step_map**：只登记 BLK 一级的行（BLK-7 → BZ-03；BLK-6 → BZ-05 / BZ-07 / LY-06）。
   - B4、B1 经 b_mapping 与成对解除查询 Q-F-25 关联，不重复映射，以免同一路径被计两次。
   - BLK-5 南半球路径在 E2 没有对应步骤，未映射。
8. **生成矩阵**：DB-N / DB-E / DB-K 在“只建表”的内存库上跑（去掉触发器与视图），以单独检验列级约束；触发器由专项用例检验。机读规格 db/spec.json：
   - required 逐行取自清单 §4；
   - 清单以引用方式写明的必填列（例如“§9.6 全部字段”“第 6.1 节全部字段”“与正式同名表同构”）列入 supplement，并逐表注明出处；
   - DB-N2 双向比对后差集为空。
9. **实现中的修正（均已通过测试）**：
   - SQLite 的 UNIQUE 报错不带约束名，所以另加触发器给出 DB-F-10c、DB-F-11b、DB-F-22b、DB-U-05c 的定位编号。
   - 删除闸门的报错同时带 `[DB-D-gate][DB-I-<表>]`，审计不可改删的报错带 DB-D-audit-immutable，批准序号的报错带 `[DB-F-08a][DB-Q-03]`，以同时满足 DB-I 与 DB-D / DB-F 两组定位。
   - v_governance_record 按清单定义改为七张权威表，去掉了误加的 formal_status_history。
   - annotation_layer.label 改为可空：清单 F15 只列了 layer_code。
   - DB-U-03c 一致性触发器改为在缺值或越界时让位，由 DB-U-03a 和 DB-E 报定位。
10. **实现补充列**（清单没有逐列写，已列入 spec 的 supplement）：
    - execution_trace_step.exec_order（实际执行序）；
    - snapshot_dependency.ref_kind（正式 / 个人 / 用户快照）；
    - step_code_retirement（废止标记）；
    - 轨迹的 input_summary 以规范化 JSON 记 `{params, reads}`，供 Q-C-06 / Q-C-10 复核实际依赖（P-42）。
11. **E + Q 预检**：封存时先写子行，再写快照行，在提交前对本快照运行连接级查询（Q-T-01/04/06/07、Q-C-01/04/05/06/10、Q-U-06、Q-B-01/02、Q-X-01/04/07）。有违规则整体回滚。“绕过预检”的反向用例都由同一组查询查出。
12. **跨库约束 DB-Q-05（branch_status_history）**：data_release 属正式库，按 §3.10 不能在用户库触发器中比对，改由查询 Q-Q-05-branch 复核。merged 是终态（DB-U-15d），所以这一项结构上成立。
13. **DB-X-05 第 6、7 条**：库层 CHECK（branch_id IS NULL）和 NOT NULL 先行拦截，造不出违例。查询保留作发布校验，测试断言违例写入被拒。
14. **DB-D-04 / 05**：
    - 删除模块保证“先写成功审计、后授权删除”，真实流程中造不出“已授权而无审计”。
    - 为单独检验库层审计条件，测试在本测试连接上以同名、同参数个数的替身替换闸门函数，并标注“DB-D-10 测试替身”。CI 只对带此标注的测试行豁免 DB-D-10。
    - 这也说明了契约 §1.2 的限度：进程内代码可以替换函数，库层只能防错、发现篡改。
15. **测试钩子**：删除入口的 hooks 与封存的 skipPrecheck / omitSnapshot / beforeDep 只在测试中传入。CI 检查非测试代码不引用这些注入点。
16. **Q-18**：引擎代码里没有任何默认日界。日界只取自正式库登记变体的内容，并核对内容哈希。没有可用变体时，判定在第 2 步阻断；即使绕过判定，构造载荷也会抛错（有测试）。日界判定用 UTC+8 钟表时间，不用真太阳时换日。
17. **Q-U-18**：审计行逐列比对输入中的日期、地点、经纬度、档案 ID 与输入 ID。occurred_at 是事件时刻，只比对完整输入时刻，不比对日期部分，以免与运行当天（2026-11-21，恰为六爻用例的日期）偶合。
18. **夹具取值【待定】**：
    - rule.track 一律取 A：契约未逐条给出取值含义。
    - C-A 子项的 is_calendar_anchor 一律为 0：尚无登记为历法锚点的子项，A-8 的指定清单不在契约中。
    - 变体 confidence 为测试值。
    - tzdata_version / tz_table_version 写“未记录”：没有 tz 数据版本。
19. **E2 范围外的路径会明确报错，不会静默计算**：
    - CFG-02 = true（经过均时差，B1 / BLK-7）；
    - gender 已知的大运（BZ-12，引擎未实现）；
    - 歧义柱的十神等派生项；
    - 时辰或未知精度的输入。

    这些属于 E3。
20. **S-6 的加载范围**：S-6 记录加载在 G2 共用世界中，两用例都会读到。表 7.6 标注它只与八字相关。六爻不读取 CFG-05 / 05W，结果不受影响。
