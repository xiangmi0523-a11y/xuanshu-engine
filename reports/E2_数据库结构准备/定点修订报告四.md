## 0 共性根因（架构层）

前几轮的阻断执行全靠“有没有映射行”。缺行即放行，默认是失效开放。

“应该有哪些映射、效果是什么”没有任何受控清单可以核验。FIX-3 只把“至少一行”当作覆盖，核的是数量，不是内容。而且这项核验只写在计算判定里：对已解除的阻断不核，发布前检查也不核。

输入同理。“未知”被折算成“安全”（缺纬度按北半球处理）。

本轮的总体改法：
- 把必备映射、必备子项关联写成受控清单。清单取自审核清单 §7.2、§3.8，这两张表经授权书 Q-16、Q-10 批准；数据仓库 verify.py 逐项核对清单原文。
- 计算判定和发布前检查共用同一个核验函数 `blockerIntegrity`。
- 计算入口另设一份可执行的覆盖复核清单。

## 1 F3-1 南半球缺坐标

| 项 | 说明 |
| --- | --- |
| 问题位置 | `db/pipeline.ts` buildPlan：`Number(inp.raw.latitude)` 得 NaN 时 `input_paths = []` |
| 执行路径 | 输入规范化层只校验“存在时必须是 6 位小数串”（DB-H-11），字段缺失则放行；随后 buildPlan 把缺失当北半球；判定看不到“南半球”标记，BLK-5 不触发；结果 FORMAL 并封存 |
| 之前为何漏检 | FIX-3 只测了“纬度为负”与“北京”两个值，没测缺失；三态被写成了布尔 |
| 性质 | 单点实现错误，背后是“未知按安全处理”的设计取向 |
| 只修表面的复发路径 | 任何可选的地理字段、任何新增的 input_path 类阻断，都会重演同样的问题 |
| 修复 | 纬度改为三态：小于 0 为南半球；大于 0 为北半球；缺失或恰为 0.000000 为“半球未知”。BLK-5 现行且半球未知时，**临时判 BLOCKED-FORMAL**（`BLOCKER_INPUT_UNKNOWN:BLK-5`），不生成快照。输入契约和必填范围都没动 |
| 修复前后 | 无纬度：FORMAL → BLOCKED-FORMAL；南半球：BLOCKED-HARD（不变）；北半球、六爻：FORMAL（不变）；BLK-5 已解除（隔离库内模拟）时缺纬度照常计算 |

**⚠ 需要用户裁决：缺纬度时怎么处理。** 当前的临时措施只是不给 FORMAL、不封存，不等于确认了“缺纬度即阻断”这条产品口径。可选方案：
- A 维持 BLOCKED-FORMAL（当前做法）；
- B 降为 NON_FORMAL 研究快照，原因写“半球未知”；
- C 八字输入把纬度改为必填（这是输入契约变更）。

另外两点也需要确认：赤道（纬度 0）算哪个半球；格式不合的纬度目前在规范化层报 DB-H-11 拒收，是否维持。

既有用例的期望随之收紧：pair 一方现行、另一方已解除，现在整次计算 BLOCKED-FORMAL，不再只是沿用映射。FIX-2 / FIX-3 中相应的 4 个用例已改写，改为两侧一起变造，或断言 PAIR_STATE。
