## 4. 代码与裁决的一致性核查

| 核查项 | 结果 | 依据 |
| --- | --- | --- |
| 1. SHICHEN 当地窗口换成 UTC | 正确 | `ws = 当地窗口起点 − 偏移`，`we = ws + 2 小时`；TZ04、TZ05、TZ06 |
| 2. 非对齐时区阻断完整四柱 | 正确 | 对齐检查在计算任何一柱之前，直接抛出 `SHICHEN_OFFSET_NOT_ALIGNED`，不返回任何柱；TZ01、TZ02、TZ03、TZ16 |
| 3. 没有猜测性时柱 | 正确 | 阻断分支之前没有赋值任何柱，`computeBazi` 无部分结果 |
| 4. 日柱双解按归一后窗口 | 正确 | `utc8DaySpan(ws, we)`；TZ05（当地亥时 → 北京子时，双解）、TZ04（当地子时 → 北京午时，单值） |
| 5. 左闭右开 [start, end) | 正确 | 日期取 `end − 1 毫秒`；交节 `jieWithin` 为 `start ≤ t < end` |
| 6. 恰好 00:00 结束不算跨日 | 正确 | 新增测试；在对齐的窗口里不会出现（窗口起点必在奇数整点），出现时必然先被 E1-1 阻断，逻辑仍按 E1-2 写对 |
| 7. 子时时干按 00:00 之后那一日 | 正确 | 子时取末日日干；TZ05（时柱丙子，按 7/11 庚日）、TZ07、契约向量 group 2、3 |
| 8. UNKNOWN 日柱与交节 | 未变 | 日柱为登记日 D；交节用当地 D 全天的 UTC 区间；TZ10～TZ15 |

阻断范围：引擎只对“这次计算”抛出阻断，不涉及命盘或草稿的创建与保存（那属于界面和存储层，未实施）。

**本轮代码改动及原因（`4855be4`，`src/bazi.ts`）**：

- 把“窗口在 UTC+8 轴上的首日、末日”抽成导出函数 `utc8DaySpan`。原因：E1-2 要求 00:00 右端点有测试，而在实际输入里这个端点只会碰上被阻断的情形，不抽出来就无法直接测。行为不变：抽出前后 74 个旧测试结果相同。
- `SHICHEN_OFFSET_NOT_ALIGNED` 的提示改为“请补充精确出生时间”，注释由【待定】改为【用户裁决 E1-1】。阻断条件与错误码不变。
